# Implementation Plan: OAuth2 Authentication API

**Branch**: `001-oauth-authentication` | **Date**: 2026-02-24 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-oauth-authentication/spec.md`

**Note**: This document outlines the complete implementation plan for Phase 1 OAuth2 authentication.

## Summary

Implement complete Google OAuth2 login flow with JWT token generation (24-hour expiration), user creation/updates, and secure token management. The backend will handle the OAuth authorization code flow, validate credentials via Google, create/update User records in PostgreSQL, generate HS256 JWT tokens, and provide protected endpoints for profile retrieval. Frontend redirects to Google for authentication, exchanges the code with the backend, and stores JWT in localStorage for subsequent API calls.

**Technical Approach:** Leverage Spring Boot's built-in OAuth2 client registration for Google, implement custom JWT token service using jjwt library, add JWT validation filter to SecurityFilterChain, create User entity with role-based access control (ADMIN/USER), and configure CORS for cross-origin frontend requests.

## Technical Context

**Language/Version**: Java 21, Spring Boot 3.3.0  
**Primary Dependencies**: Spring Security 6 (OAuth2 client + resource server), Spring Data JPA, jjwt (JWT library v0.12+), Hibernate/Lombok  
**Storage**: PostgreSQL 15+ (managed service, ACID compliance for user transactions)  
**Testing**: Manual testing per constitution (no automated unit tests)  
**Target Platform**: Backend API service on Render.com free tier (Docker container)  
**Project Type**: web-service (REST API backend)  
**Performance Goals**: 1000 concurrent users, 10,000 total registered users  
**Constraints**: OAuth callback <500ms, JWT validation <100ms, user lookup <50ms, 24-hour token expiration  
**Scale/Scope**: 3-4 main authentication endpoints, 1 User entity, 1 JWToken utility class, 1 AuthService layer, CORS + security headers

### Source Code (Task Management Backend)

**Selected Structure**: Single backend project with layered architecture (Option 1 adapted)

```text
backend/
├── src/main/java/com/karthik/
│   ├── config/
│   │   ├── JwtConfig.java           # JWT properties and secret loader
│   │   ├── SecurityConfig.java      # Spring Security + OAuth2 configuration
│   │   └── CorsConfig.java          # CORS configuration for frontend
│   ├── entity/
│   │   ├── User.java                # User JPA entity with role enum
│   │   └── UserRole.java            # Enum: ADMIN, USER
│   ├── dto/
│   │   ├── LoginRequest.java        # Empty request body
│   │   ├── LoginResponse.java       # { redirectUrl: "..." }
│   │   ├── CallbackRequest.java     # { code, state }
│   │   ├── UserDTO.java             # { id, email, name, role, avatar, bio, createdAt }
│   │   └── ErrorResponse.java       # { success, error, timestamp }
│   ├── repository/
│   │   └── UserRepository.java      # JpaRepository with findByGoogleId, findByEmail
│   ├── service/
│   │   ├── AuthService.java         # OAuth2 flow, JWT generation, user creation
│   │   ├── JwtTokenService.java     # JWT creation, validation, claims extraction
│   │   └── OAuthCallbackService.java# Google code exchange, user sync
│   ├── controller/
│   │   └── AuthController.java      # @PostMapping("/api/auth/login"), (@GetMapping("/api/auth/callback"), etc.)
│   ├── security/
│   │   ├── JwtAuthenticationFilter.java  # Validate JWT from Authorization header
│   │   ├── JwtAuthenticationProvider.java # Extract claims from token
│   │   └── JwtAuthenticationToken.java   # Token wrapper for Spring Security
│   ├── exception/
│   │   ├── OAuthException.java      # Google OAuth failures
│   │   ├── JwtException.java        # JWT validation failures
│   │   └── UserCreationException.java # User persistence failures
│   └── util/
│       └── SecurityUtils.java       # Helper: getCurrentUserId(), isUserAdmin()
├── src/test/java/com/karthik/
│   └── (manual testing from spec checklist, no unit tests)
├── src/main/resources/
│   └── application.yaml             # Spring OAuth2 client config (see spec)
└── pom.xml                          # Dependencies: spring-boot-starter-security, jjwt, etc.
```

**Structure Decision**: Backend uses layered Spring Boot architecture with clear separation of concerns:
- **Controller**: HTTP request entry point, delegates to service
- **Service**: Business logic for OAuth flow, JWT generation, user management
- **Repository**: Data access layer (JPA)
- **Security**: Custom JWT filter and authentication provider
- **Entity/DTO**: Data transfer and persistence models
This aligns with Spring best practices and constitution principle of separation of concerns.

## Complexity Tracking

**Status**: ✅ NO VIOLATIONS - All design decisions align with constitution.

**Rationale for Selected Architecture**:

| Decision | Why Needed | Simpler Alternatives Considered | Rejection Reason |
|----------|------------|--------------------------------|------------------|
| Layered (Service/Repository) | Clear separation of concerns, testability, Spring convention | Monolithic controller with direct DB | Violates constitution principle of separation; reduces reusability; harder to test |
| Custom JWT Filter | Stateless auth on every request, flexibility | Use Spring Session | Adds session storage complexity; defeats stateless design; violates "minimal dependencies" |
| Spring Security OAuth2 | Production-grade, Google provider built-in | Manual OAuth2 implementation | Wheel reinvention; more security vulns; unmaintainable |
| DTO pattern | Type safety, API contract independence | Direct entity serialization | Tight coupling to DB schema; API changes risky; validation inconsistent |

**No unjustified violations detected**. Phase 1 design is clean and maintainable.
